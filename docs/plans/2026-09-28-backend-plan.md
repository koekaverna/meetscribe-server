## Этап 3. Новый эндпоинт: дорожка плюс список отрезков (L)

Причина: клиент шлёт чанки по одному, пакет из восьми остаётся пустым, задержка на чанк втрое больше времени распознавания.

Контракт `POST /v1/audio/transcriptions/clips`:

- Вход: `file`, `model`, `language`, `clips` в JSON: список `{start, end, speaker}` в секундах. Без `clips` сервер режет по VAD, как сейчас.
- Выход: `segments` с полями как в `verbose_json` плюс `clip_index` и `speaker`, и `failed_clips` с причиной.
- Запас по краям отрезка задаётся параметром `pad_ms`, временные метки возвращаются в координатах дорожки.

Реализация:

- Один вызов `BatchedInferencePipeline.transcribe(audio, clip_timestamps=clips)` на дорожку.
- Одно декодирование файла и один захват слота на дорожку.
- Ограничение длины отрезка 30 с проверяется на входе, ошибка 422.
- Проверка отключения клиента между пакетами, чтобы брошенный запрос не занимал карту.
- Для длинных дорожек промежуточный прогресс не отдаётся, таймаут клиента 600 с должен покрывать час аудио с запасом. По замерам час аудио занимает около минуты.

Проверка: текст совпадает со старым путём на тех же отрезках, время на диаризованной дорожке не менее чем вдвое меньше, видеопамять стабильна.

## Отложено, требует отдельного решения

- **Parakeet v3.** WER 7.1%, но преимущество может объясняться пересечением с обучающими данными. Требует около 7 ГБ видеопамяти, не выдаёт оценки достоверности, пишет английский текст на музыке. Возвращаться после появления размеченных встреч.
- **GigaAM-v3.** Обычный вариант теряет текст на клипах 20–30 с. Вариант с пунктуацией близок к turbo по WER, но угадал 12 английских терминов из 54.
- **Нормализация громкости.** Гипотеза из аудита, не измерялась. Проверять на эталоне.
- **Штраф за повторы.** Не измерялся, риск подавить настоящие повторы в речи.

## Что сознательно не делаем

- Последовательное декодирование: хуже или в пределах шума, с большой моделью даёт зацикливания.
- Промпт и ключевые слова по умолчанию: измеренный вред. Поля в API остаются.
- Отключение VAD.
